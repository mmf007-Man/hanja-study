## 2. Phase 03 마감 작업: 실기기 손글씨 검증 및 `verified` 승격

자동화 테스트([test_prototype.js](../prototype/stroke-assist/test_prototype.js))는 정답 메디안 좌표를 그대로 입력해 5,932획의 알고리즘·데이터 정합성을 확인한 것이며, 실제 손가락/마우스 필기 오차를 검증한 것은 아니다. [작업 체크리스트](00-작업-일정표.md#03-획-보정-시제품-검증) 원칙에 따라 **실기기 검증 통과 후에만 `strokeStatus`를 `"verified"`로 승격**한다.

### 2.1 실기기 테스트 대상 환경

- **모바일 터치**: iOS Safari (iPhone/iPad 손가락 입력), Android Chrome (모바일 손가락 입력)
- **데스크톱**: PC Chrome / Edge (마우스 입력)
- **테스트 대상**: [prototype/stroke-assist/index.html](../prototype/stroke-assist/index.html) (`http://<로컬IP>:8000/prototype/stroke-assist/`)

### 2.2 검증용 표본 한자군 (4개 그룹)

1. **기본·단순 획**: `一`, `十`, `九`, `木`, `火`, `水`
2. **복잡·다획 한자**: `漢`(14획), `學`(16획), `道`(12획), `馬`(10획), `國`(11획), `觀`(25획)
3. **변별성 필수 유사 쌍**: `土` vs `士` (가로획 폭 역전 방지), `日` vs `曰` (종횡비 역전 방지)
4. **한국 정자 보정·이중 렌더링 대표군**:
   - `internal`/교체 보정 대표: `者`(9획), `都`(12획), `視`(12획), `兎`(8획), `晩`(11획), `遺`(16획), `逸`(12획), `餘`(16획), `我`(7획), `義`(13획), `近`(8획)
   - KanjiVG `stroke` 모드 7자 전수: `厖`, `姉`, `顔`, `爲`, `硏`, `絶`, `郞`

### 2.3 허용 오차 실측 및 조정 기준

현재 [stroke-engine.js](../prototype/stroke-assist/js/stroke-engine.js)의 `PRESETS.normal` 기준값:
- `startTolerance: 165` / `endTolerance: 185` / `avgTolerance: 140` (1024×1024 기준)
- `minCosine: 0.60` (약 53° 이내) / `minRatio: 0.55` ~ `maxRatio: 1.65`

**측정 및 기록 절차**:
1. 성인·어린이(실사용자 포함)가 각 표본 글자를 `보통(Normal)` 프리셋으로 필기하며 시제품 디버거 패널의 `startDist`, `endDist`, `avgTrajectoryDist`, `lengthRatio`, `angleDiffDeg` 실측치를 기록한다.
2. **정상 필기 거절(False Reject)** 사례(특히 짧은 획, 점 `丶`, 꺾임 획 `ㄱ`/`辶`)가 반복되면 해당 오차 항목 임계값을 슬라이더로 조정해 수용 가능한 `normal` / `lenient` 수치를 도출한다.
3. **오류 필기 통과(False Accept)** 사례(역방향 획, `土`에 위 가로를 길게 쓴 경우, `日`을 정사각형으로 쓴 경우, 필순 뒤바뀐 입력)가 통과하지 않는지 교차 확인한다.
4. 확정된 임계값을 `StrokeEngine.PRESETS` 및 [02-학습-채점-획보정-명세서.md](02-학습-채점-획보정-명세서.md)에 반영한다.

### 2.4 `strokeStatus: draft → verified` 승격 조건

- [ ] iOS Safari · Android Chrome · PC Chrome 3개 환경에서 표본 한자군 정상 입력 통과 및 오류 입력 차단 확인 완료
- [ ] 어린이 실필기 관찰 결과 및 확정 `PRESETS` 수치 문서화 완료
- [ ] 모바일 터치 드래그 시 화면 스크롤/바운스/줌 간섭 0건 확인
- [ ] 위 조건 충족 후 [data/characters.json](../data/characters.json)의 검증 완료 한자 `strokeStatus`를 `"verified"`로 일괄(또는 검증된 범위부터 순차) 승격하고 `python scripts/validate_data.py` 통과 확인

## 4. 테스트 전략 및 필수 검증 체크리스트

### 4.1 테스트 계층 구조

1. **데이터 무결성 검증 (CI 필수 게이트)**: `python scripts/validate_data.py`
2. **엔진 단위·통합 테스트 (Vitest)**: 출제, 채점, 복습 상태 머신, 스토리지/백업, 획 판정(`StrokeEngine`)
3. **브라우저·모바일 터치 E2E 테스트 (Playwright)**: 실제 DOM 인터랙션, 새로고침 이어하기, 모바일 뷰포트(`hasTouch: true`) 터치 드로잉 및 스크롤 고정 확인 + 실기기 수동 QA

### 4.2 출제·세션 엔진 검증 체크리스트

- [ ] **기본 20문항 & 유형 균등 배분**:
  - 1유형 선택 시 20문항, 2유형 선택 시 10·10문항, 3유형 선택 시 7·7·6문항, 4유형 선택 시 5·5·5·5문항 생성 확인
  - 유형별 배분 수는 유지된 채 출제 순서가 무작위로 섞이는지 확인
- [ ] **20자 이상/미만 반복·중복 규칙**:
  - 출제 가능 한자가 20자 이상인 범위에서는 한 회차 내 동일 한자가 중복 출제되지 않는지 확인
  - 출제 가능 한자가 20자 미만인 범위(예: 20자 미만 단원 조합) 선택 시, 1라운드 전수 출제 후 누적 출제 횟수가 적은 한자 순(직전 연속 중복 금지)으로 반복해 20문항을 채우는지 확인
  - 정답 한자가 다른 단원에서 절대 보충되지 않는지 확인
- [ ] **객관식 4지선다 중복 정답 방지**:
  - 한자 → 뜻·음 객관식(`樂` 등 복수 독음)에서 정답 쌍 외의 다른 올바른 뜻·음·`allowedSounds`가 오답 보기 3개에 포함되지 않는지 확인
  - 뜻·음 → 한자 객관식에서 제시된 모든 뜻·음 쌍과 일치하는 다른 정답 한자가 오답 보기에 포함되지 않으며 보기 4개가 모두 서로 다른 한자인지 확인
  - 선택 단원 오답 후보가 3개 미만일 때만 같은 교과서 타 단원에서 부족분만 보충하는지 확인
- [ ] **덜 출제한 뜻·음 쌍 우선 & 최초 표시 카운트**:
  - `exposureCount`가 적은 쌍이 우선 선택되고, 동률 시 `lastExposedAt`이 오래된 쌍이 선택되는지 확인
  - 문항 생성 시점이 아니라 **실제 화면 최초 표시 시점**에만 카운트가 +1 되는지 확인
  - 동일 문항에서 새로고침·이어하기 시 `exposureCount`와 `lastExposedAt`이 중복 갱신되지 않는지 확인
- [ ] **쓰기 출제 필터**: `strokeStatus !== 'verified'`인 한자가 쓰기 유형 후보에서 제외되는지 확인

### 4.3 채점 및 정답 공개 검증 체크리스트

- [ ] **공백 무시 및 엄격 일치**:
  - 뜻/음 입력 시 `" 한 나라 "` → `"한나라"`와 동일하게 정답 인정 확인
  - 뜻 주관식에서 어미 변형(`즐거울`), 동의어, 1글자 오타(`한나리`) 모두 오답(0점) 처리 확인
  - 음 주관식에서 29자 등록 `allowedSounds`(예: `年` `연`, `六` `육`, `樂` `낙`)는 정답 인정, 미등록 임의 두음 변환은 오답 처리 확인
- [ ] **복수 독음 쌍 불일치 판정**:
  - `樂` 출제 시 `즐겁다` + `락` → 2점(정답), `즐겁다` + `낙` → 2점(정답), `노래` + `악` → 2점(정답)
  - `樂` 출제 시 **`즐겁다` + `악`** 또는 **`노래` + `락` / `낙`** 입력 시 → **0점**, `errorType: 'pair_mismatch'` 기록, 입력 칸에 주황 경고(`개별 존재하나 쌍 불일치`) 표시 및 오답 복습 큐 등록 확인
- [ ] **제출 버튼 활성화 조건**:
  - 뜻·음 중 한쪽만 선택/입력하거나 공백만 입력한 상태, 또는 뜻·음 → 한자 객관식에서 한자를 선택하지 않은 상태에서 일반 제출 버튼이 비활성화되는지 확인
- [ ] **`'모르겠어요'` 처리**:
  - 입력·선택 없이도 즉시 클릭 가능하며, 클릭 시 `0점`, `outcome: 'dont_know'` 기록, **즉시 정답 공개**, 오답 복습 등록 확인
  - `'모르겠어요'` 시 뜻·음 개별 오답(`meaning_error`/`sound_error`)과 구분되어 기록되는지 확인
- [ ] **진행 중 정오·점수 표시 및 정답 일괄 공개**:
  - 일반 제출 직후에는 상단/피드백 배지에 **정오 여부와 누적 점수만 즉시 표시**하고, 틀렸을 때의 **실제 정답 내용(텍스트·한자·올바른 쌍)**은 회차 종료 후 결과 화면에서 한꺼번에 공개되는지 확인
- [ ] **중도 이탈 및 두 가지 정답률 산출**:
  - `[학습 끝내기]` 중도 종료 시 화면에 표시된 미제출 문항은 `'abandoned'`(0점, 복습 미등록)로 처리되고 미표시 문항은 제외되는지 확인
  - 결과 화면의 **문항 정답률**(확정 응답 기준, 중도 이탈 제외)과 **뜻·음 개별 정답률**(일반 제출 기준, `'모르겠어요'`·중도 이탈 제외)이 규칙대로 계산되는지 확인

### 4.4 중도 이탈·이어하기 & 복습 큐 검증 체크리스트

- [ ] **중도 이탈 & 이어하기**:
  - 20문항 중 일부(예: 7문항) 풀이 후 브라우저 새로고침 또는 탭 종료 후 재접속 시 이어하기 상태 복원 확인
  - 이어하기 시 기존에 구성했던 문항 순서·객관식 보기 4개 순서·이미 노출된 문항의 `exposureCount`가 변하지 않는지 확인
- [ ] **복습 큐 상태 전이 (연속 2회 / 초기화 / 복귀)**:
  - 같은 복습 회차에서 항목 `A`를 연속 2회 정답 시 `status: 'completed'` 전이 및 과거 오답 이력 보존 확인
  - `A` 정답(1회) → `A` 오답(또는 `'모르겠어요'`) → `sessionStreak === 0` 초기화 확인
  - 미완료 항목이 있는 상태에서 새 학습 회차를 시작하면 `sessionStreak`이 `0`으로 초기화되는지 확인
  - `completed` 상태 항목을 이후 일반/도전 학습에서 다시 틀리면 자동으로 `needs_review`로 복귀(`sessionStreak = 0`)하며 이전 완료 이력이 보존되는지 확인
- [ ] **복습 형식 유지 & 보기 재구성**:
  - 객관식 오답은 객관식 복습(원래 정답 쌍 유지, 오답 보기 3개 및 순서 새로 구성), 주관식 오답은 주관식 복습으로 출제되는지 확인
  - 같은 한자를 객관식·주관식에서 모두 틀린 경우 두 복습 항목이 독립적으로 완료 판정되는지 확인
- [ ] **재출제 1문제 간격 & 마지막 1개 삽입**:
  - `A` 출제 직후 바로 `A`가 연속 출제되지 않고 다른 문제 1개 뒤에 다시 출제되는지 확인 (`A → B → A`)
  - 미완료 복습 항목이 `A` 1개만 남았을 때, 선택한 단원의 **다른 한자(`!== A`)** 일반 문제 1개를 사이에 삽입한 뒤 `A`를 재출제하는지 확인

### 4.5 획 보정 캔버스 & 모바일 크로스브라우저 검증 체크리스트

- [ ] **매 획 판정 및 정자 스냅 / 실패 보호**:
  - 한 획 입력 후 `pointerup` 시 통과 획만 정자 SVG로 즉시 교체되는지 확인
  - 실패한 획이 절대 정자 획으로 자동 교체되지 않고, 기존 성공 획을 보존한 채 재입력을 유도하는지 확인
- [ ] **쓰기 3회 연속 실패 점선 가이드**:
  - 동일 획에서 연속 3회 판정 실패 시 해당 획의 점선 메디안 경로와 시작점 가이드가 자동으로 표시되는지 확인
- [ ] **`土/士`, `日/曰` 및 `fill`/`stroke` 이중 렌더링**:
  - `土` 1획을 길게 쓰거나 `日` 2획을 가로로 넓게 쓰면 `special_char_rule`로 거절되는지 확인
  - `fill` 모드(`漢`, `者`, `遺` 등)와 `stroke` 모드 7자(`厖`, `姉`, `顔`, `爲`, `硏`, `絶`, `郞`) 모두 깨짐 없이 렌더링·판정되는지 확인
- [ ] **모바일 터치 스크롤 간섭 없음 (iOS Safari · Android Chrome)**:
  - 캔버스 영역 위에서 상하/좌우 빠른 획 드래그, 세로 내리긋기(`丨`), 삐침(`丿`) 입력 중 페이지 전체 스크롤이나 iOS 고무줄 바운스, 풀투리프레시가 발생하지 않는지 확인
  - 화면 회전(세로↔가로) 또는 모바일 가상 키보드(주관식 입력 시) 여닫힘 후에도 캔버스 좌표(`getBoundingClientRect` 대비 `1024×1024` 매핑)가 어긋나지 않는지 확인

### 4.6 가족 프로필·하루 도전·백업 검증 체크리스트

- [ ] **프로필 전환 격리**: 프로필 A에서 푼 오답·출제 횟수·진행 중 회차가 프로필 B에 섞이지 않는지 확인
- [ ] **하루 도전**: 같은 날짜에 프로필 A와 프로필 B가 하루 도전을 시작했을 때 동일한 문제 세트가 출제되는지 확인
- [ ] **JSON 백업 내보내기/가져오기**:
  - 백업 JSON 다운로드 → `LocalStorage` 초기화 → 백업 JSON 업로드 시 프로필·복습 큐·출제 이력·완료 기록이 100% 복원되는지 확인
  - 손상된 JSON 또는 잘못된 형식 파일 업로드 시 기존 `LocalStorage` 데이터가 훼손되지 않고 오류 메시지를 표시하는지 확인
