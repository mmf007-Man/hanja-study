## 2. 데이터 스키마 명세

### 2.1 한자 카탈로그 (`data/characters.json`)

최상위 구조는 `schemaVersion`(`1`), `dataVersion`(`"0.2.0"`), `updatedAt`(`"YYYY-MM-DD"`), `readingSourceFile`, `characters[]`로 구성된다.

```json
{
  "id": "hanja-6A02",
  "character": "樂",
  "codePoint": "U+6A02",
  "readings": [
    {
      "sound": "락",
      "meanings": ["즐겁다"],
      "allowedSounds": ["낙"]
    },
    {
      "sound": "악",
      "meanings": ["노래"]
    }
  ],
  "readingStatus": "verified",
  "strokeData": {
    "provider": "animcjk_ko",
    "key": "6A02",
    "version": "c63765b1"
  },
  "strokeStatus": "draft",
  "readingVerifiedAt": "2026-10-19",
  "readingSourceIds": ["unit-07-hanja-6A02"]
}
```

| 필드 | 타입·규칙 | 설명 |
|---|---|---|
| `id` | `hanja-<HEX4>` (불변) | `hanja-` + 유니코드 대문자 4자리 16진수. 뜻·음·단원을 수정해도 ID는 변경하지 않는다. 정자 교정 시(`豊` `U+8C4A` → `豐` `U+8C50`, `畵` `U+7575` → `畫` `U+756B`)에만 정자 코드포인트 ID로 교체한다. |
| `character` | 단일 한자 문자 | `[\u3400-\u9fff\uf900-\ufaff]` 범위 1글자. NFKC/호환 정규화로 자형을 변형하지 않는다. |
| `codePoint` | `U+<HEX4>` | `character`의 실제 유니코드 코드포인트와 정확히 일치해야 한다. |
| `readings[]` | 객체 배열 (음 중복 금지) | `{ sound, meanings[], allowedSounds? }` 구조. 허용 키 외 다른 키는 금지한다. |
| `readings[].sound` | 한글 음절 문자열 | 교과서 원문 음 그대로 유지(예: `륙`, `녀`, `로`, `락`). |
| `readings[].meanings` | 비어 있지 않은 문자열 배열 | 같은 음에 연결된 교과서 원문 뜻 목록. 어미 변형·유의어를 임의로 추가하지 않는다. |
| `readings[].allowedSounds` | 선택 문자열 배열 | 두음법칙(초성 `ㄴ`→`ㅇ`, `ㄹ`→`ㄴ`/`ㅇ`, 모음·종성 동일) 사전 검수 확정 시에만 해당 묶음에 종속 연결. 미적용 묶음에는 필드 자체를 생략한다. |
| `readingStatus` | `pending` \| `draft` \| `verified` | `verified`는 `readingSourceIds`와 `readingVerifiedAt`이 전사 기록과 일치할 때만 허용한다. |
| `strokeData` | `{ provider, key, version }` | `normalized_strokes.json`의 획 데이터 참조 메타데이터. |
| `strokeStatus` | 4상태 열거형 | 아래 **2.2절** 참고. |

### 2.2 `strokeStatus` 4상태 정의

| 상태값 | 의미 | `strokeData` 요건 | 쓰기 문제 출제 |
|---|---|---|---|
| `pending` | 획 데이터 탐색·매핑 대기 | 선택(없음 가능) | **제외** |
| `draft` | `normalized_strokes.json` 연결 및 1차 자형·총획 정합 완료, **실기기 허용 오차 테스트 대기** (현재 637자 상태) | 필수 (`provider`, `key`, `version`) | **제외** (시제품 테스트 전용) |
| `verified` | 교과서 필순·자형 대조 및 시제품 손글씨 허용 오차 테스트 최종 통과 | 필수 (`provider`, `key`, `version`) | **출제 허용** |
| `unavailable` | 제공처·자체 보정으로도 유효한 획 데이터를 확보할 수 없음 | 없음 | **제외** |

> **중요 규칙**: 오픈소스 제공처에 글자가 존재하거나 `normalized_strokes.json`에 매핑되었다는 이유만으로 `verified`로 간주하지 않는다. 반드시 시제품 손글씨 허용 오차 검증을 통과한 항목만 `verified`로 승격한다.

### 2.3 교과서 단원 데이터 (`data/textbooks/*.json`)

- 파일명과 `id`는 반드시 일치해야 한다(`chunjae-middle-hanja-2022-ahn.json`).
- `schemaVersion`, `dataVersion`은 `characters.json`과 일치해야 한다.
- `units[]`는 `number` 1부터 순차 증가하며, `id`는 `<bookId>-unit-<NN>` 형식을 따른다.
- `characterIds[]`는 교과서 수록 순서 그대로 유지하며, 앱은 이 배열 순서를 임의로 가나다/유니코드 순으로 재정렬하지 않는다.
- `counts`는 `{ units, entries, uniqueCharacters }` 실측 집계와 정확히 일치해야 한다.

### 2.4 정규화 획 데이터 (`data/strokes/normalized_strokes.json`)

- **좌표계**: Top-Down SVG `viewBox: "0 0 1024 1024"` (원점 좌상단 `(0,0)`, X 우향 `0→1024`, Y 하향 `0→1024`).
- **원천 변환 규격**:
  - AnimCJK Ko / ZhHant / MakeMeAHanzi (`0 0 1024 1024`, Y상향): $X_{std}=X$, $Y_{std}=900-Y$
  - KanjiVG (`0 0 109 109`, Y하향): $X_{std}=X\times\frac{1024}{109}$, $Y_{std}=Y\times\frac{1024}{109}$
  - Internal (자체 보정 13자): Top-Down 정규화 및 벡터 융합·순서 교정
- **항목 필수 필드**: `id`, `character`, `codePoint`, `sound`, `meanings`, `provider`, `sourceVersion`, `renderMode`(`"fill"` 또는 `"stroke"`), `strokeCount`, `strokes[]`(SVG Path 문자열), `medians[]`(획별 `[x, y]` 중심선 좌표 배열), `auditStatus`(`"verified_candidate"` \| `"corrected_internal"`), `needsManualReview`(`false`), `isHighPriority159`, `notes`.
- **무결성 불변식**: 모든 항목은 `len(strokes) == len(medians) == strokeCount > 0`을 만족해야 하며, 중심선 점 좌표는 유효 마진(`[-100, 1124]`) 내에 있어야 한다.

## 3. 향후 급수 시험 확장 및 CSV/엑셀 ↔ JSON 파이프라인

1차 MVP(교과서 637자) 이후 한국어문회 등 급수 시험 데이터를 추가할 때, 비개발자 검수 작업과 데이터 무결성을 양립하기 위해 **CSV/엑셀 원본 양식 ↔ JSON 변환 파이프라인**을 사용한다.

### 3.1 향후 급수 시험 묶음 확장 구조

기존 `data/textbooks/`와 병렬로 `data/exams/<org>-<level>.json`(또는 통합 `collections/` 구조)을 두어, 동일한 `data/characters.json`의 `hanja-<CODEPOINT>` ID를 참조한다.
- 마스터 카탈로그(`characters.json`)에는 한자 고유 정보(정자 코드포인트, 대표/시험별 뜻·음 묶음, `allowedSounds`, `strokeData`)를 중복 없이 저장한다.
- 필요 시 `characters[]`에 선택 필드 `examGrades`(예: `[{ "org": "한국어문회", "grade": "6급", "sourceVersion": "..." }]`)를 추가하되, 교과서 전용 뜻·음과 시험 기관 지정 대표 훈·음이 다를 경우 출처 태그(`sourceScope`)로 구분해 기존 교과서 채점 원문이 오염되지 않도록 격리한다.

### 3.2 CSV/엑셀 원본 입력 양식 (UTF-8 BOM CSV / XLSX)

| 컬럼명 | 필수 | 형식·예시 | 비고 |
|---|---|---|---|
| `collection_id` | Y | `chunjae-middle-hanja-2022-ahn` 또는 `kome-grade-6` | 대상 묶음 ID |
| `unit_or_group` | Y | `01` (단원/분류 번호) | 수록 순서 유지 |
| `unit_title` | Y | `한문은 처음이지?` | 단원/분류 제목 |
| `source_page` | Y | `14` | 출처 페이지 또는 회차 번호 |
| `order_in_unit` | Y | `1` | 단원 내 수록 순번 |
| `character` | Y | `樂` | 단일 정자 한자(NFKC 금지) |
| `reading_text` | Y | `락 즐겁다 / 악 노래` | [`scripts/reading_format.py`](../scripts/reading_format.py) 규격(`쉼표`=복수 뜻, `슬래시(공백없음)`=공통 뜻 복수 음, ` / `=독립 쌍) |
| `allowed_sounds` | N | `락:낙` | 두음법칙 검수 확정 음 (`기준음:허용음`, `;` 구분) |
| `radical` / `total_strokes` | 권고 | `木` / `15` | 쓰기 힌트용 부수·총획 (부록/공인 표기 기준) |
| `reading_status` | Y | `verified` | 원문 대조 완료 시에만 `verified` |

### 3.3 양방향 변환 흐름

1. **Import (CSV/XLSX → JSON)**:
   - `character`에서 `hanja-<CODEPOINT>` 자동 생성 및 호환 한자(Compatibility Ideographs) 여부 경고.
   - `reading_text`를 `parse_reading()`으로 파싱해 `readings[]` 생성 및 `allowed_sounds`의 초성 `ㄴ/ㄹ` 두음법칙 유효성 검증.
   - 기존 `characters.json`에 동일 ID가 있으면 기존 `strokeData`/`strokeStatus` 보존 및 뜻·음 충돌 검사.
2. **Export (JSON → CSV/XLSX)**:
   - 검수자(보호자/편집자)가 엑셀에서 전체 단원 목록, 복수 독음, 두음법칙, `strokeStatus` 현황을 한눈에 대조할 수 있도록 `characters.json` + `textbooks/*.json` + `normalized_strokes.json` 요약을 UTF-8 BOM CSV로 추출한다.

## 4. 앱 런타임 출제 자격 및 제외 규칙

학습 앱은 데이터를 로드한 뒤 아래 필터를 통과한 항목만 문제 후보 풀에 편입한다.

| 출제 유형 | 필수 조건 (모두 충족 시 출제 가능) | 미충족 시 처리 |
|---|---|---|
| **뜻·음 문제** (한자↔뜻·음 객관식·주관식) | - `readingStatus === "verified"`<br>- `readings.length > 0`<br>- 객관식인 경우 같은 교과서 전체에서 중복 정답·중복 보기를 제외한 유효 오답 후보 **3개 이상** 확보 가능 | - `readingStatus != "verified"` 한자 제외<br>- 4지선다 불가 시 해당 문항 제외/대체, 범위 내 전체 불가 시 시작 전 안내 및 `'시작'` 비활성화 |
| **쓰기 문제** | - `readingStatus === "verified"`<br>- **`strokeStatus === "verified"`** (`pending`, `draft`, `unavailable` 일체 제외)<br>- `normalized_strokes.json`에서 `id` 매칭 및 `strokes.length === medians.length > 0` 확인<br>- 목표 한자 1자 특정용 부수/총획 메타데이터 존재 | - `strokeStatus !== "verified"` 한자는 쓰기 후보에서 **자동 제외**<br>- 선택한 단원 범위 내 쓰기 가능한 한자가 **0자**이면 쓰기 유형 선택 시 시작 전 안내 배너 표시 및 `'시작'` 비활성화(또는 쓰기 유형 토글 비활성 안내) |

## 5. 4단계 데이터 업데이트 · 검증 · 배포 · 복구 절차

데이터를 수정하거나 새 단원/급수/보정 획을 반영할 때는 반드시 아래 4단계를 순서대로 수행한다.

### 1단계: 4종 자동 검사 (Validation)

변경 후 아래 4개 검증 스크립트를 모두 실행해 `PASS`를 확인한다. 하나라도 실패하면 2단계로 넘어갈 수 없다.

1. **`python scripts/validate_data.py`**
   - JSON 중복 키, 한자 코드포인트/ID 불일치, `readingStatus == "verified"`의 전사 출처 일치 여부, `allowedSounds` 두음법칙 음운 규칙, 교과서 단원/순서/집계 일치 여부, `strokeStatus`·`strokeData` 형식 검증.
2. **`python scripts/verify_stroke_mapping.py`**
   - `raw_mapped.json` 및 `mapping_summary.json`과 `characters.json`의 637자 ID/글자 100% 일치 확인.
3. **`python scripts/verify_normalized_strokes.py`**
   - `normalized_strokes.json`의 637자 100% 매핑, `len(strokes) == len(medians) > 0`, 좌표 유효 범위(`[-100, 1124]`) 확인.
4. **`node prototype/stroke-assist/test_prototype.js`**
   - `StrokeEngine` 단위 테스트(Font/TopDown 변환, 역방향 획 거절, `土/士`·`日/曰` 변별 규칙), 637자 전 획 통과 스캔, `app.js` 문법 검사.

### 2단계: 미리보기 및 원문 대조 (Preview)

- **시제품 뷰어 확인**: `prototype/stroke-assist/index.html`에서 수정·보정된 한자의 자형(`fill`/`stroke`), 필순 애니메이션, 손글씨 허용 오차를 실제 터치/마우스로 확인한다.
- **원본 대조**: 뜻·음 변경 시 `data/sources/chunjae-middle-hanja-2022-ahn-pages/` 해당 쪽수 PNG와, 필순·자형 변경 시 `chunjae-middle-hanja-2022-ahn-stroke-checks/` 및 교과서 부록(194~207쪽)과 대조하고 Diff를 검토한다.

### 3단계: 버전 갱신 및 반영 (Publish)

- **버전 규칙**: Semantic Versioning(`MAJOR.MINOR.PATCH`) 적용.
  - `PATCH` (`0.2.x`): 오탈자 수정, `allowedSounds` 보완, 획 좌표 미세 보정.
  - `MINOR` (`0.x.0`): 새 교과서 단원/급수 묶음 추가, `strokeStatus` 일괄 승격(`draft` → `verified`).
  - `MAJOR` (`x.0.0`): `schemaVersion` 변경 등 구조적 호환성 변경.
- **동기화 대상**: `data/characters.json` 및 `data/textbooks/*.json`의 `dataVersion`·`updatedAt`을 동일하게 갱신하고, `prototype/stroke-assist/js/strokes-bundle.js` 등 앱 배포 번들을 재생성한 뒤 Git 커밋·태그(`data-vX.Y.Z`)를 남긴다.

### 4단계: 백업 · 복구 및 하위 호환 (Backup & Rollback)

- **데이터 롤백**: 문제 발견 시 직전 Git 태그(`data-vX.Y.Z`)의 `data/` 및 번들을 복원해 재배포한다.
- **학습 기록 하위 호환**:
  - 사용자 `LocalStorage` 기록에는 `dataVersion`, `textbookId`, `unitId`, `characterId`(`hanja-<CODEPOINT>`), `readingKey`를 함께 저장한다.
  - 한자의 뜻·음이 일부 수정되더라도 `hanja-<CODEPOINT>` ID가 유지되므로 기존 학습 이력·누적 출제 횟수·복습 상태가 끊어지지 않는다.
  - 정자 코드포인트 교체(`豊`→`豐` 등)처럼 ID 자체가 바뀌는 예외 시에는 마이그레이션 매핑 테이블(`deprecatedIdMap`)을 두어 앱 로드 시 또는 JSON 백업 불러오기 시 사용자 기록 ID를 안전하게 이관한다.
